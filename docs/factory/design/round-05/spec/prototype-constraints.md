# Native prototype constraints

Figma Starter cannot use prototype variables/conditionals without an upgrade ([Figma Learn](https://help.figma.com/hc/en-us/articles/14506587589399-Use-variables-in-prototypes)). No upgrade is authorized. Use explicit context variants where target selection, dispatch or a mutation changes the logical return; do not claim plain Figma Back remembers an earlier application context.

- Board/Table/List preserve the project/environment query, planning identity and selected item. Layout choice must remain available before intake and with no selection, not be disabled merely to force a demo journey.
- Read-only nested source/menu/detail returns may pop native history. Mutation/dispatch/activation returns use an explicit current snapshot.
- Manual Factory/CI review Cancel preserves its originating view even after switching target. Accepted Factory dispatch, later provider start, CI queued and CI completed are distinct observations.
- Ordinary workflow/trigger configuration is ordinary navigation, not a View later record detour. Start with real Draft/off bindings. Explicit enablement creates Enabled with no invocation; only a later matched event produces its qualified invocation. CI host-owned rules remain pending until observed active.
- Workflow definitions do not own mutable binding state. Version detail must not display a global automatic-bindings-off claim after a rule has been enabled or paused.
- Pausing future admissions is not cancellation of active work, and does not disable manual runs or independent host-owned rules.
- Source, plan, retained Work, native thread, invocation and external CI run remain distinct. The auto issue238 branch never borrows manual issue237 receipts.

Static fixture navigation is not application, accessibility or client-parity proof. Common native controls outside these bounded design journeys are listed explicitly; none sends a real agent, CI, webhook, Git or permission operation.
